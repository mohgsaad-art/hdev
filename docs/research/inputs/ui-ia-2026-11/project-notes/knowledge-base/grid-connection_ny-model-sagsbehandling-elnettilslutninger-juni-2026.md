## 1. Background and purpose

- Interest in connecting new projects to the electricity grid has "exploded" ("Interessen for at få tilsluttet nye projekter til elnettet er eksploderet").
- Energinet states it is fully focused on expanding the grid as fast as possible and accommodating connection interest.
- To strengthen case processing (**sagsbehandling**) of grid-customer projects (**netkundeprojekter**) and promote efficient use of available capacity, Energinet is introducing:
  1. **Sharpened, phase-divided maturity requirements** (skærpede og faseopdelte modenhedskrav), and
  2. An **adjusted model for prioritisation in case processing** (justeret model for prioritering i sagsbehandlingen).
- These measures are explicitly stated to be in line with:
  - **The European Commission's guidance in this area** ("Europa-Kommissionens vejledning på området") — the specific EU guidance document is not named further in this text. **[unclear from source — exact EU document title/number not given]**
  - **The Danish Energy Agency's (Energistyrelsen) "Guidance to collective electricity supply undertakings on prioritisation of grid connection requests"** ("Vejledning til kollektive elforsyningsvirksomheder om prioritering af nettilslutningsanmodninger"), dated **February 2026**. (Note: this guidance document itself is separately available among the project's files, e.g. `ENS Vejledning til kollektive elforsyningsvirksomheder om prioritering af nettilslutningsanmodninger.pdf` and `ny-prioriteringsmodel-for-tilslutning-til-energinets-elnet-1-februar-2026.pdf`.)
- The pamphlet explicitly states these measures **do not affect Energinet's work on larger grid-expansion projects** ("større netudbygningsprojekter"), where overall need is assessed via a holistic/comprehensive assessment ("helhedsvurdering").
- The maturity-requirement table is explicitly scoped to **connection of installations to the transmission grid** ("MODENHEDSKRAV FOR TILSLUTNING AF ANLÆG TIL TRANSMISSIONSNETTET") — i.e., this is Energinet's TSO-level process, not automatically the process used by local distribution grid companies (netvirksomheder/DSOs), though the underlying Danish Energy Agency guidance is aimed at "kollektive elforsyningsvirksomheder" generally (a term covering both TSO and DSOs) and the document notes the goal of "more uniform treatment of customers across voltage levels" (see §3 below).

## 2. Maturity requirements (Modenhedskrav) — stage-gate model

### 2.1 Structure

- On **1 February 2026**, Energinet already implemented a first set of new requirements for grid customers wanting their project "screened" (screening).
- These requirements are now **expanded to cover more phases** of the connection process ("tilslutningsforløbet").
- The model is built as a **stage-gate model** ("stage-gate-model") intended to ensure steadily increasing project maturity as a project nears a connection agreement: "the closer a project is to entering a grid connection agreement, the more certain it must be that the project can be realised."
- There are **three maturity gates (modenhedsgates)**, each with requirements that must be fulfilled and **verified by Energinet** before the project can move into the next phase:

| Gate | Trigger point | Description |
|---|---|---|
| **Gate 1 (MG1)** | Before screening starts | Requirements must be met and verified by Energinet before Energinet starts the screening process for a project. |
| **Gate 2 (MG2)** | Before maturation (modning) starts | Requirements must be met and verified before Energinet starts the maturation phase. |
| **Gate 3 (MG3)** | Before a grid connection agreement is signed | Requirements must be met and verified before Energinet enters into a nettilslutningsaftale (grid connection agreement). |

The requirements implemented on 1 February 2026 become, going forward, **part of Gate 1**.

### 2.2 Gate 1 (MG1) requirements — before screening

| Requirement | Description |
|---|---|
| **Documentation of project area** (Dokumentation for projektareal) | The grid customer must be able to show documentation of the ability to acquire land/rights for the project area. |
| **Documentation of timeline** (Dokumentation for tidsplan) | The grid customer must submit a timeline showing the project's expected major milestones. |
| **Documentation of planning basis for the project area** (Dokumentation for planmæssigt grundlag for projektarealet) — *new requirement* | Can be satisfied by: (a) an adopted plan basis (vedtaget plangrundlag) for the specific project; (b) the project being located in an area designated in the municipal plan (kommuneplan) for the intended purpose; or (c) a declaration from the relevant municipality of political intent to initiate planning for the specific project. |

*(These three items plus the pre-existing 1 Feb 2026 requirements together make up Gate 1.)*

### 2.3 Gate 2 (MG2) requirements — before maturation (modning) starts

| Requirement | Description |
|---|---|
| **Start-up deposit** (Opstartsdepositum) — *new* | The grid customer must pay a start-up deposit of **DKK 500,000**, covering part of the costs of screening and maturation. |
| **Filled-out delivery list for maturation** (Leveranceliste til modning udfyldt) | Must be completed before maturation can start. Ensures all necessary information/deliverables are in place before maturation begins. Includes, among other things, a single-line diagram, including transformer and cable information. |
| **Draft guarantee** (Udkast til garanti) | Grid customer must submit a draft guarantee, including naming the guarantor. The guarantee is finalised/posted at the signing of the grid connection agreement. |
| **Other new requirements** | (i) The final counterparty to the grid connection agreement must be established/fixed; (ii) a ramp-up plan (optrapningsplan) for the installation must be filled out. |

### 2.4 Gate 3 (MG3) requirements — before signing the grid connection agreement

| Requirement | Description |
|---|---|
| **Local plan approved** (Lokalplan godkendt) | Documentation that the local plan (lokalplan) has been politically approved, OR that all planning-related matters are fully clarified. |
| **Timeline showing Gate 3 requirements met within 12 months** | Grid customer must submit a timeline showing that Gate 3 requirements can be fulfilled **within 12 months from the start of maturation**. |
| **Other new requirements** | Permit for a direct line received (tilladelse om direkte linje modtaget), if relevant. |

### 2.5 Implementation on existing (in-flight) projects

To maximise the effect of the new requirements, the model is also being rolled out to projects already in the pipeline. Treatment depends on which phase (screening, maturation/modning, or establishment) the project is in. Energinet states its existing technical/documentation/financial-security requirements remain in force regardless.

| Project status | New requirements that apply |
|---|---|
| **Projects awaiting a screening-and-maturation agreement, and all new/incoming projects** | Must meet **all Gate 1** requirements |
| **Projects with a signed screening-and-maturation agreement, not yet started in maturation**¹ | Must meet the **Gate 2** requirements before the maturation project can start: documentation of planning basis for the project area; start-up deposit; filled-out delivery list for maturation; draft guarantee; timeline showing Gate 3 requirements achievable within 12 months; local plan approved before grid connection agreement |
| **Projects already in maturation¹, or with an already-signed grid connection agreement** | **No new requirements apply** |

¹ *A maturation project is considered "started" once the grid customer has received a maturation project plan (modningsprojektplan).*

Energinet states it will notify grid customers directly which requirements apply to their specific project and how/when to fulfil them, in line with the new prioritisation order (see §3), on a rolling basis.

### 2.6 Exception provision (Undtagelsesbestemmelse)

- For projects that **can only be connected in 4 years or more**² due to a need to expand the transmission grid, **certain maturity requirements can be relaxed**.
- This relaxation applies when Energinet has assessed that the project's planning/realisation horizon — as a result of circumstances attributable to Energinet — extends significantly longer than normal.
- Where the exception applies, Energinet will engage in dialogue with the relevant grid customer to agree how the maturity requirements will be met.

² *Footnote in source: "Jf. forventning i screeningsafgørelse" — i.e., per the expectation stated in the screening decision (screeningsafgørelse).*

### 2.7 Q&A — Maturity requirements (key points, translated)

- **If a project doesn't meet the maturity requirements:** Energinet enters into dialogue with the customer on how to bring the project into compliance, and will advise on the deficiencies and how to remedy them.
- **Time allowed to meet requirements:** Energinet will give ongoing notice of when it expects to move a project into the next phase — i.e., requirements must be met before the project proceeds. **Gate 2 requirements must be met no later than 6 months after the screening decision (screeningsafgørelse) is issued**; within that same period, the material must also be verified by Energinet.
- **Documenting the planning basis:** Must show municipal support for placing the project on the desired site — e.g. via existing plan conditions, consistency with the municipal plan's designated use of the area, or a written declaration from the municipality that it is working to enable the project from a planning perspective. **If this documentation cannot be delivered, the project cannot be started.**
- **If the municipality doesn't approve the local plan as expected:** Energinet will make a factual assessment of the cause of the delay. If there is a justified/reasonable cause, a period will be set within which local-plan approval must be obtained before the project can move to the next phase.
- **Deposit refund on cancellation:** Yes — on cancellation or completion of a project, any remaining balance is refunded, while any cost overrun is invoiced.
- **If a project doesn't require local-plan approval:** A local-plan approval is not itself mandatory, but planning matters must be clarified. If the customer can document that they have a municipal permit to establish the installation, that documentation satisfies the requirement.
- **Rationale for the exception provision:** In some cases, large grid expansions are needed before an installation can be connected, making some maturity-model requirements hard to meet given the long time horizon. Where the exception applies, Energinet dialogues with the customer on how requirements will be fulfilled.
- **Changing previously submitted information:** Energinet assesses the materiality of the change. A material change can trigger a **new screening**, requiring the project to be resubmitted.

Contact for questions on maturity requirements: **netkundecenter@energinet.dk**

## 3. Prioritisation model (Prioriteringsmodel)

### 3.1 Purpose and scope

- Energinet, based on the Danish Energy Agency's guidance, is adjusting its current model for prioritising case processing of grid connection requests.
- The adjustment ensures Energinet's **grid dimensioning and capacity allocation account for ordinary/expected organic growth** in the existing customer base (i.e., the normal, expected development in consumption among small consumers).
- The model also promotes efficient use of available capacity by **prioritising new production projects in areas currently dominated by consumption, and vice versa** (new consumption projects in production-dominated areas).
- The model is based on principles developed in dialogue with the grid/network companies (netvirksomhederne), intended to reflect prioritisation needs across the grid as a whole and to achieve **more uniform treatment of customers across voltage levels**.
- **Prioritisation in case processing does not affect projects that have already signed a grid connection agreement (nettilslutningsaftale)** — it only affects projects still queued for screening/maturation.
- Prioritisation category is **dynamic**: a project can change category after its initial submission (indmelding), depending on which criteria it meets as circumstances evolve.

### 3.2 Prioritisation criteria/categories (as described in the narrative text)

| Category | Description | Rationale/legal basis given |
|---|---|---|
| **Projects using reserved capacity, and projects categorised as organic growth** | E.g. the ordinary and expected development in consumption among small consumers. Projects drawing on capacity already reserved for them are prioritised first — they do not wait behind projects requiring grid expansion. | The Danish Energy Agency (Energistyrelsen) regards it as an integral part of the obligation under **§ 20 of the Danish Electricity Supply Act (elforsyningsloven)** that grid dimensioning and capacity allocation account for ordinary and foreseeable organic growth in the existing customer base. |
| **Politically prioritised projects — mandated connections** (Politiske prioriterede projekter — pålagte tilslutninger) | Projects Energinet has been instructed/mandated to handle (e.g. by political directive). In addition to customer-submitted projects, Energinet can be mandated to expand the grid for specific projects. The prioritisation category depends on the individual project. | — |
| **Projects connected within the customer's existing bay/field (felt), without change in network capacity** | Requires only limited new grid capacity and can usually be done without material physical changes to substations or the grid (e.g. adding a battery to an existing production facility with no desire for new grid consumption). | — |
| **Grid-relieving projects (netaflastende projekter):** new consumption in the transmission grid's production-dominated areas, and vice versa | E.g., adding an electrolysis plant in an area that otherwise mostly has production capacity. The **area type** follows the areas underlying Energinet's **producer payment (producentbetaling)** scheme. The **installation type** (consumption vs. production) is determined by the direction in which the largest exchange capacity is requested. Where a project requests the same capacity in both directions, it is categorised as the *opposite* of the area type it is located in — whichever classification benefits the project owner in final prioritisation. | — |
| **Grid utilisation (netudnyttelse)** | Secondary prioritisation criterion: projects are prioritised by how easy they are to connect. Projects that fit within existing substation space are processed ahead of projects requiring new bays/fields and/or acquisition of new substation land. | — |

### 3.4 Customer cases (Kundecases) — illustrative, hypothetical examples

The pamphlet stresses these are **hypothetical** examples; actual placement always depends on individual case processing.

1. **Adding a battery installation to a solar (PV) project that already has a signed grid connection agreement.** If the change is to an existing project and does not require new bays, and the previously agreed exchange capacity is unchanged, it will going forward be placed in **priority group 2**. If increased capacity is requested, the project is categorised as **group 3 or 6**, depending on the area.
2. **Customer applies to connect a consumption installation in a production-dominated area.** Will fall in **priority group 3, 4, or 5**. The final group depends on whether the installation connects in an existing field (**group 3**) or within the station area (**group 4**); if the connection requires expansion of the station area, it is categorised as "other" (**group 5**).
3. **Customer wants to install a large solar (PV) installation in a production-dominated area.** Falls in **priority group 6, 7, or 8**, and is thus processed *after* any consumption projects in production-dominated areas. Adding more consumption to production-dominated areas generally relieves the area and can create room for more production; the actual time to connection of additional production installations in a production-dominated area may become **shorter** if more consumption is connected in that area first.

### 3.5 Q&A — Prioritisation model (key points, translated)

- **Can an already-submitted project be deprioritised?** Depends on the project's stage. If already in maturation (modning), it is not affected by the changes. If still queued awaiting screening or maturation, prioritisation can change depending on which criteria the project meets.
- **Is prioritisation by case-processing criteria discriminatory?** No — per Energinet, using published criteria to prioritise grid connection requests, targeted at utilisation of available grid capacity, aligns with both the European Commission's recommendations and the Danish Energy Agency's guidance, and is common practice in many European countries.
- **Can a customer be reprioritised if they change their project?** Up to screening, projects can be up- or down-prioritised depending on which criteria are met — an improving change leads to reprioritisation. Once in the maturation phase, a project cannot be up- or down-prioritised unless changes are made to the project itself.
- **Can a project get permanently stuck in the queue?** Energinet states it continues to aim to give all project developers an answer within a reasonable time; current case-processing times (sagsbehandlingstider) are published on Energinet's website. A customer cannot get permanently stuck in the queue; Energinet states it is working to make the process more efficient.
- **Will the prioritisation model change in future?** The model is meant to promote more efficient, targeted use of resources for projects that further utilisation of available grid capacity. It is designed in light of the current situation, and the need for adjustment is continuously assessed.
- **How is a project classified as consumption vs. production for the priority criterion?** Determined by which direction requests the largest exchange capacity. Where a project requests equal capacity in both directions, it is categorised as the *opposite* of the area type it is located in — benefiting the project owner in final prioritisation.
- **Is there always room for new consumption in a production-dominated area?** No. If an area is dominated by weather-dependent production installations, there is no guarantee of enough transmission capacity for any given new consumption load. However, a consumption installation is more likely to be accommodated than a production installation would be. In the best case, adding consumption to the area can relieve the grid and create room for more production.

## 5. Relevance to the HDEV sizing & modelling tool

This document is directly relevant to depot/fleet electrification timelines and should inform any grid-connection-timeline assumptions in the tool, with the following caveats:

1. **Applies to Energinet (TSO/transmission-level) connections**, explicitly for "tilslutning af anlæg til transmissionsnettet." Most individual depot connections in Denmark will interface with the local distribution grid company (netvirksomhed/DSO), not directly with Energinet — so this specific stage-gate/deposit/prioritisation mechanism may not apply verbatim to a typical depot project. However, very large depots (e.g. multi-MW hubs, mega-depots, or clusters requiring dedicated substation capacity) could fall under transmission-adjacent processes, and the document itself states the underlying Danish Energy Agency guidance aims for "more uniform treatment of customers across voltage levels" — implying DSOs are expected to adopt broadly similar prioritisation logic. **[This inference about DSO adoption is not explicitly stated as fact in this document — flagging as an assumption, not confirmed by the source.]**
2. **Concrete timeline benchmarks usable for sizing/scenario assumptions** (if the modelled connection is transmission-level or DSO practice mirrors it):
   - Gate 2 maturity requirements must be met **within 6 months** of the screening decision.
   - Gate 3 (final) requirements must be shown achievable **within 12 months** of maturation start.
   - A **DKK 500,000 start-up deposit** is required at Gate 2 (before maturation begins) for transmission-level projects — a real, sourced cost figure usable in a depot financial model if the project is transmission-connected.
   - Projects needing significant grid expansion may face a **4-year-or-more** connection horizon, per the exception provision's threshold — a useful reference point for "worst case" grid-constrained depot scenarios.
3. **Prioritisation logic is directly relevant to depot siting strategy:** a new HDEV depot is a new **consumption** project. Per §3.2–3.4, a new consumption project sited in a **production-dominated grid area** is prioritised *ahead of* new production projects there (grid-relieving category), and may see faster connection than the same depot sited in a consumption-dominated area (which competes with more consumption capacity demand and falls into ordinary/lower-priority queue treatment). This suggests **grid-area characterisation (production- vs. consumption-dominated, per Energinet's producer-payment area definitions) is a potentially decisive input for depot siting and connection-timeline estimation** in the tool — but note the document also cautions there is **no guarantee** of available capacity even for favourably-classified consumption projects.
4. **Organic growth carve-out** (§20 elforsyningsloven): small/incremental existing-customer load growth is protected/prioritised in grid dimensioning — relevant if modelling phased depot expansion (e.g. adding chargers incrementally to an existing connection) versus a new, large, discrete connection request, which would not benefit from this carve-out and would instead be queued/prioritised under the criteria above.
