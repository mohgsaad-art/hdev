- Energinet states it is fully focused on expanding the grid as fast as possible to meet connection interest.

## Part 1 — Tightened maturity requirements ("Skærpede modenhedskrav") — Stage-Gate model

### Overview
Existing maturity requirements are supplemented by new requirements built on a **stage-gate model**. The purpose is to ensure that grid-customer projects have the maturity level appropriate to each step of the grid connection process — the closer a project is to signing a grid connection agreement, the more certain it must be that the project can actually be realised. There are **three maturity gates (modenhedsgates)**, each with requirements that must be met before a project can proceed to the next phase of the connection process.

Context: Energinet already implemented an initial set of screening-entry requirements on **1 February 2026**. Those requirements are now being **expanded to cover more phases** of the connection process (they become part of Gate 1 going forward).

### The three gates (for connection to the transmission grid)

| Gate | When it applies | Purpose |
|---|---|---|
| **Gate 1 (MG1)** | Before Energinet can start the **screening** process for a project | Requirements for MG1 must be fulfilled and verified by Energinet before screening starts |
| **Gate 2 (MG2)** | Before Energinet can start the **maturation/development phase** ("modning") for a project | Requirements for MG2 must be fulfilled and verified by Energinet before maturation starts |
| **Gate 3 (MG3)** | Before a **grid connection agreement** ("nettilslutningsaftale") can be entered into | Requirements for MG3 must be fulfilled and verified by Energinet before the agreement is signed |

### Detailed requirements per gate

**Gate 1 (MG1) — requirements before screening can start**

| Requirement | Description | Status |
|---|---|---|
| Documentation for project area (Dokumentation for projektareal) | Grid customer must show documentation of the ability to acquire land/rights for the project area | New requirement |
| Documentation for timeline (Dokumentation for tidsplan) | Grid customer must submit a timeline showing the project's expected main milestones | New requirement |
| Documentation for planning basis for the project area (Dokumentation for planmæssigt grundlag for projektarealet) | Must show, e.g.: an adopted local plan for the specific project; the project is located in an area designated for the intended use in the municipal plan (kommuneplan); or a statement from the relevant municipality of political intent to initiate planning for the specific project | New requirement |
| Start-up deposit (Opstartsdepositum) | Grid customer must pay a start-up deposit of **DKK 500,000**, covering part of the costs of screening and maturation | New requirement |
| Final counterparty to the grid connection agreement must be fixed | — | Additional new requirement |
| Ramp-up plan (Optrapningsplan) for the facility must be completed | — | Additional new requirement |
| *(Note: the requirements implemented 1 February 2026 — the original screening-entry requirements — become part of MG1 going forward)* | | |

**Gate 2 (MG2) — requirements before maturation/development can start**

| Requirement | Description |
|---|---|
| Delivery list for maturation completed (Leveranceliste til modning udfyldt) | Ensures all necessary information/deliverables are in place before maturation starts; includes e.g. single-line diagram, including transformer and cable information |
| Draft guarantee (Udkast til garanti) | Grid customer must submit a draft guarantee, including naming the guarantor; the guarantee is finalised upon signing of the grid connection agreement |

**Gate 3 (MG3) — requirements before the grid connection agreement can be signed**

| Requirement | Description |
|---|---|
| Local plan approved (Lokalplan godkendt) | Documentation that the local plan (lokalplan) has been politically approved, or that all planning matters are fully resolved |
| Direct-line permit received (Tilladelse om direkte linje modtaget), if relevant | Additional requirement |
| Timeline showing MG3 requirements met within 12 months | Grid customer must submit a timeline showing that MG3 requirements can be met within **12 months** from the start of maturation |

### Implementation on existing (in-flight) projects

The new model is also applied to ongoing projects, differentiated by which phase (screening, maturation, or establishment) the project is in. Existing technical/documentation/financial-security requirements remain in force regardless.

| Project status | New requirements applied |
|---|---|
| Projects awaiting screening and maturation agreement, and all new projects reported to Energinet | Must fulfil **all** requirements |
| Projects with a signed screening and maturation agreement, not yet started in maturation¹ | Must meet Gate 2 requirements before the maturation project can start: Documentation for planning basis for the project area; Start-up deposit; Delivery list for maturation completed; Draft guarantee; Timeline showing MG3 met within 12 months; Local plan approved before grid connection agreement |
| Projects already in maturation¹, or with a signed grid connection agreement | **No new requirements apply** |

¹ A maturation project is considered "started" once the grid customer has received a maturation project plan ("modningsprojektplan").

Energinet states it will inform grid customers directly and on a rolling basis about which requirements apply to their specific project, in line with the new prioritisation order (see Part 2).

### Exception clause (Undtagelsesbestemmelse)

For projects that can only be connected **4 years or more** in the future (per the expectation stated in the screening decision, "screeningsafgørelse") due to the need for transmission grid expansion, **certain maturity requirements can be relaxed**. This applies when Energinet has assessed that the project's planning and realisation horizon — as a consequence of Energinet's own circumstances — extends significantly longer than normal. If invoked, Energinet enters into dialogue with the relevant grid customer to agree how the maturity requirements will be met.

### Q&A — Maturity requirements (selected, paraphrased/translated)

- **What happens if my project doesn't meet the maturity requirements?** Energinet will enter dialogue with the customer about how to bring the project into compliance, and will provide guidance on deficiencies and how to remedy them.
- **How long do I have to meet the maturity requirements?** Energinet will inform on a rolling basis when it expects to start the project's next phase; requirements must be met before that phase starts. **Gate 2 requirements must be met no later than 6 months after the screening decision is issued**, and Energinet must verify the material within that period.
- **How do I document planning basis for the project area, and what if I can't?** Must show municipal support for siting the project on the desired area (via existing plan status, alignment with the municipal plan, or a written statement of intent from the municipality). If documentation cannot be provided, **the project cannot be started**.
- **What if the municipality doesn't approve my local plan as expected?** Energinet performs an objective assessment of the cause of delay; if there is a reasoned/objective cause, a period will be set within which local plan approval must be obtained before the project can move to the next phase.
- **If I cancel my project, do I get my deposit back?** Yes — upon cancellation or completion of a project, any remaining balance is settled/refunded, while excess usage is invoiced.
- **What if my project doesn't require local plan approval?** A local plan approval is not itself mandatory, but planning matters must be resolved; documentation of municipal permission to establish the facility satisfies the requirement.
- **Why is an exception clause needed?** Some projects require major grid expansions before connection is possible, making some maturity requirements hard to meet on a long timeline; Energinet will dialogue with the customer on how requirements are met in such cases.
- **What if I change information I've already given Energinet?** Energinet assesses the materiality of the change; a material change can trigger a new screening and require the project to be re-submitted.

## Part 2 — New prioritisation model ("Ny prioriteringsmodel") for case processing

### Purpose and basis
Based on the Danish Energy Agency's guidance, Energinet is adjusting its current model for prioritising case processing of grid connection requests. The adjustment:
1. Ensures Energinet's network dimensioning and capacity allocation account for **ordinary and expected organic growth** in the existing customer base (i.e., ordinary/expected development in consumption among small consumers) — grounded in **Elforsyningsloven § 20** (see above).
2. Promotes **efficient use of available capacity** by prioritising the establishment of new electricity **production** projects in areas currently dominated by **consumption**, and vice versa.
3. Is based on principles developed in dialogue with the network/grid companies ("netvirksomhederne"), intended to reflect the need for prioritisation across the grid as a whole and more consistent treatment of customers across voltage levels.

The document stresses that prioritisation in case processing **only affects projects sorted before they start screening** — it does **not** affect projects already in maturation or that have signed a grid connection agreement.

### Prioritisation categories/criteria (described in prose)

| Category | Description | Example given |
|---|---|---|
| **Projects using reserved capacity, and projects categorised as organic growth** | Highest priority — projects using capacity already reserved for them go first and do not wait behind projects requiring grid expansion. "Organic growth" = ordinary and expected development in consumption among small consumers | — |
| **Politically prioritised projects — mandated connections ("pålagte tilslutninger")** | Energinet can be instructed/mandated to build grid connections for specific projects, in addition to customer-submitted projects; each such project's priority category is decided individually | — |
| **Projects connecting within the customer's existing field/bay, without change in grid capacity** | These require only limited new grid capacity and can usually be completed without significant physical changes to stations or the grid | E.g., adding a battery to an existing production facility with no additional grid consumption sought |
| **Grid-relieving projects ("netaflastende projekter")**: new consumption in the transmission grid's production-dominated areas, and vice versa | Area type follows the areas underlying Energinet's producer payment ("producentbetaling"). Facility type (consumption vs. production) is determined by the direction with the largest requested exchange capacity; if a project requests equal capacity in both directions, it is categorised as the *opposite* of the area type it sits in (to the project owner's benefit for prioritisation) | E.g., adding an electrolysis facility in an area otherwise dominated by production capacity |
| **Network utilisation ("netudnyttelse")** — secondary criterion | Projects are secondarily prioritised by how easy they are to connect to the grid: projects using space at existing stations are processed before projects requiring new bays/fields and/or acquisition of new station land | — |

### Prioritisation process flow (as illustrated in the document)

Reconstructed sequence (the source presents this as a flow diagram; some ordering nuance may be lost in text extraction — **treat the exact diagram layout as approximate**):

1. **Project referred to Energinet** ("Projekt henvises til Energinet")
2. **Check that Gate 1 maturity requirements are fulfilled** ("Tjek af modenhedskrav Gate 1 er opfyldt") — gating step before sorting into priority groups
3. Projects sorted into **priority groups 1–8**, plus a separately-handled category for politically mandated connections:

| Priority group | Category |
|---|---|
| **1** | Projects that use reserved capacity |
| **2** | Projects connecting in the customer's existing field, without change in grid capacity |
| **3** | Organic-growth projects — can be connected within the station area |
| **4** | Organic-growth projects — connected in the customer's existing field |
| **5** | Organic-growth projects — other ("øvrige") |
| **6** | Grid-relieving projects — can be connected within the station area |
| **7** | Grid-relieving projects — connected in the customer's existing field |
| **8** | Grid-relieving projects — other ("øvrige") |
| *(unnumbered, handled case-by-case)* | Politically mandated connections — handled and individually placed into the categories above |

### Illustrative customer cases (hypothetical; Energinet stresses actual placement always depends on concrete case processing)

- **Adding a battery to a solar project that already has a signed grid connection agreement**: if it's a change to an existing project not requiring new bays/fields (e.g., adding a battery to an already-processed solar plant) and the already-agreed exchange capacity is unchanged, it goes in **priority group 2**. If increased capacity is requested, it becomes **category 3 or 6** depending on the area.
- **A consumption facility seeking connection in a production-dominated area**: lands in **group 3, 4, or 5** depending on whether it connects in an existing field (group 3) or within the station area (group 4); if it requires station-area expansion, it's "other" (**group 5**).
- **A large solar (production) facility in a production-dominated area**: lands in **group 6, 7, or 8**, and is therefore processed *after* any consumption projects in production-dominated areas. The document notes that adding consumption in production-dominated areas generally relieves the area and can create room for more production — so time-to-connection for additional production facilities in such an area **may actually shorten** if more consumption is connected there first.

### Q&A — Prioritisation (selected, paraphrased/translated)

- **Can my project be deprioritised even though I've already submitted it?** Depends on project stage — projects already in maturation are unaffected; projects still queued for screening or maturation can have their priority changed depending on which criteria they meet.
- **Isn't prioritisation in case processing discriminatory?** No — Energinet states that using published criteria to prioritise grid connection requests, targeted at utilisation of available network capacity, aligns with both European Commission recommendations and the Danish Energy Agency's guidance, and is common practice in many European countries.
- **Can I be reprioritised if I change my project?** Up to the point of screening, projects can be up- or down-prioritised depending on which criteria are met after a change; once a project is in the maturation phase, it cannot be up- or down-prioritised unless changes are made to the project.
- **Can I get stuck indefinitely in the queue?** Energinet states it aims to give all project developers an answer within reasonable time; current case processing times are published on Energinet's website. A customer should not get permanently stuck in the queue; Energinet is working to make the process more efficient.
- **Will the prioritisation model change in future?** It is designed considering the current situation, and Energinet continuously assesses the need to adapt it.
- **How is a project classified as consumption vs. production for prioritisation?** By the direction with the largest requested exchange capacity; if equal in both directions, the project is classified as the opposite of the area type it's located in (to the project owner's benefit).
- **Is there always room for new consumption in a production-dominated area?** No — e.g., if an area is dominated by weather-dependent production facilities, there may not always be enough transmission capacity for any given new consumption load. However, a consumption facility is generally more likely to be accommodated than another production facility in such an area, and in the best case added consumption can relieve the grid, creating room for more production.

## Relevance to the HDEV sizing & modelling tool

This document is directly relevant to depot/fleet grid-connection timeline modelling because it governs **how long and under what conditions a large new electrical load (e.g., an HDEV depot or charging hub) will wait to be screened, matured, and formally connected to the grid** in Denmark:

- **Applies to transmission-grid connections specifically** ("tilslutning af anlæg til transmissionsnettet") — the document's detailed gate requirements are stated for transmission-level connections. Whether/how an equivalent stage-gate model applies at distribution level (more relevant for most depot connections) is **[unclear from source]** — this leaflet does not address distribution-network (netvirksomhed/DSO) connection processes explicitly, only referencing that the underlying prioritisation *principles* were developed "in dialogue with netvirksomhederne" (the grid/network companies) for consistency "on tværs af spændingsniveauerne" (across voltage levels).
- **A large depot project would likely be classified as a "consumption" (forbrug) project**, and its case-processing priority would depend on: (a) whether it uses previously reserved capacity (group 1), (b) whether it fits within an existing field/bay without capacity change (group 2), or (c) — most likely for a new depot needing incremental capacity — whether it falls under the "organic growth" category or must be prioritised purely by network utilisation ease (groups 3–5), which depends heavily on whether the local area is production-dominated or consumption-dominated and whether the connection fits within existing station infrastructure.
- **Concrete timeline data points usable in a tool**: Gate 2 requirements must be met **within 6 months of the screening decision**; Gate 3 requires a timeline showing MG3 requirements achievable **within 12 months of maturation start**; the **DKK 500,000 start-up deposit** is a real, quotable cost input for depot project financial planning; the **4-year-plus exception threshold** is a useful marker for when a depot project should expect materially longer, case-by-case-negotiated timelines due to transmission bottlenecks.
- **Planning/permitting dependency**: Gate 1 and Gate 3 both hinge on municipal planning status (kommuneplan alignment or lokalplan approval) — meaning depot siting decisions are coupled to local municipal planning processes, not purely technical/electrical capacity, which is an important modelling dependency (site selection risk, not just grid capacity risk).
- **Area-type sensitivity**: a depot's time-to-connection could be *shorter* if sited in a production-dominated area (since new consumption there is prioritised as "grid-relieving"), which is a non-obvious, quotable siting insight for the tool's depot-siting/timeline module.
